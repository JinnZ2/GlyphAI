Executive Summary
GlyphAI's premise — a loyalty-bound personal agent that filters commerce through user-defined values instead of vendor-defined metrics — turned out to be the right idea at exactly the right time. Between September 2025 and September 2026, the industry built an entire agentic-commerce stack around the problems GlyphAI was designed to solve: Google launched and then donated the Agent Payments Protocol (AP2) to the FIDO Alliance [VERIFIED 2026-09-09], OpenAI and Stripe shipped the Agentic Commerce Protocol (ACP) [VERIFIED 2026-09-09], Google and Shopify launched the Universal Commerce Protocol (UCP) [VERIFIED 2026-09-09], Coinbase's x402 moved to the Linux Foundation [VERIFIED 2026-09-09], and Mastercard and Google open-sourced Verifiable Intent, a cryptographic binding between a user's instructions and an agent's actions [VERIFIED 2026-09-09]. At the same time, Amazon v. Perplexity went the other way from what the district court first held: on August 4, 2026 the Ninth Circuit vacated the preliminary injunction, holding on that record that it is Amazon's customers, not Perplexity, who access Amazon's systems when they direct an agent to shop for them [VERIFIED 2026-09-09] — while both Shopify and Cloudflare moved, on commercial rather than legal grounds, to make cryptographically signed bot identity (Web Bot Auth, RFC 9421) the price of full-speed admission for agent traffic [VERIFIED 2026-09-09].
The two deepest findings of this research are architectural. First, the ManipulationDetector should evolve from a three-keyword rule list into a three-layer detector: a signed, community-maintained pattern database (still pure stdlib), a structural heuristic layer grounded in the Mathur/Gray taxonomies that the FTC and EU regulators actually cite, and an optional model layer for those who accept dependencies. Every flag should carry a regulatory mapping — the FTC's Rule on Unfair or Deceptive Fees (in force since May 2025) [VERIFIED 2026-09-09], DSA Article 25, and the forthcoming EU Digital Fairness Act [PROJECTED] turn GlyphAI's flags from opinions into legally anchored categories. Second, Jibbelink should not compete with UCP or ACP; it should be repositioned as the negotiation and values layer that sits above them — an Ed25519-signed, DID-identified, alternating-offers protocol whose utility function is literally the user's glyph. The codebase already contains the correct instincts (honest User-Agent, robots.txt compliance, mock data labeled as mock); this report shows how to harden those instincts into cryptographic identity, price-history truth anchoring, and a twelve-month phased build sequence that preserves the stdlib-only core while defining exactly which optional dependencies buy which capabilities.

1. Baseline: What GlyphAI Is Today, Audited Honestly
GlyphAI is a roughly 1,700-line [MEASURED 2026-09-09: 1,391 lines across the top-level modules; 2,853 including examples and tests], zero-dependency Python project organized as a linear pipeline: a Glyph value profile (JSON, values 0–1) feeds a ManipulationDetector, a GeoPriceAnalyzer, and a RecommendationEngine, with an optional JibbelinkNegotiator stub and a CLI as the reference caller. The engineering culture visible in the code is unusually disciplined for a project at this stage: diagnostics go to stderr so stdout stays machine-parseable, the fetcher obeys robots.txt with no bypass flag by deliberate design, prices that cannot be verified are reported as unknown rather than free, and regional in-store pricing is explicitly labeled as mock data rather than silently invented. The glyph schema itself is the most original asset in the repository — eleven value dimensions including manipulation_tolerance, ethical_threshold, DIY_viability, repairability_bias, barter_compatibility, and a loyalty_enforcement block containing an actual oath — and nothing else in the open-source landscape encodes consumer values this explicitly.
The audit also exposes four structural gaps that the rest of this report addresses. The detector recognizes only three tactics (fake urgency, suspicious discount, subscription trap) against an academic taxonomy of at least fifteen pattern types in seven categories, and its severities are hardcoded rather than calibrated. The Jibbelink message format is unsigned — JibbelinkSecurity.md sketches a signature block but no code produces or verifies one — and the format predates the entire 2025–2026 agentic-commerce protocol wave, so it specifies no identity, discovery, or interop story. Price history does not exist as a subsystem, which means the SUSPICIOUS_DISCOUNT check can only compare a claimed was-price against a claimed now-price, exactly the self-reported data a manipulative vendor controls. Finally, the glyph's auto_learn flags are declared but never read by any logic, and the loyalty oath is a string in JSON rather than anything enforceable. None of these gaps is a criticism — they are the natural state of a Phase-0/1 project — but each one maps to a specific, research-backed architectural upgrade.

2. The Manipulation-Detection Engine
2.1 The taxonomy gap: three flags against a fifteen-type reality
The academic foundation for this entire domain is Mathur et al.'s 2019 crawl of roughly 11,000 popular shopping websites, which found 1,818 dark-pattern instances on 1,254 sites (~11.1%), spanning 15 pattern types in 7 categories [VERIFIED 2026-09-09] — and the authors stress this is a lower bound because the crawler only saw text-based interfaces on product, cart, and checkout pages (Mathur et al., arXiv). The most prevalent patterns were Activity Notifications (fake or unverifiable "someone just bought this" popups), Low-Stock Messages, and Countdown Timers; the study also identified 22 third-party vendors selling dark-pattern widgets as a service [VERIFIED 2026-09-09], which means manipulation is a supply-chain problem with reusable signatures — excellent news for a pattern-database approach (Mathur et al., arXiv). The crawl dataset itself was released on GitHub [VERIFIED 2026-09-09], giving GlyphAI a real, citable corpus to seed and calibrate against rather than inventing examples.
The taxonomy most regulators reach for is Gray et al.'s 2018 CHI refactor of Brignull's original twelve patterns into five higher-order categories — Nagging, Obstruction, Sneaking, Interface Interference, and Forced Action [VERIFIED 2026-09-09] — which is the vocabulary most subsequent academic literature and regulatory guidance builds on (Yu-kai Chou analysis). Measured against this landscape, GlyphAI's current detector covers fragments of two Mathur categories (Urgency, Scarcity) plus one Sneaking pattern (forced subscription continuity). The upgrade is not to bolt on more keyword lists but to restructure detection around the taxonomy itself: each pattern type gets a detector module, an evidence extractor, a severity model, and a regulatory citation. Finding from the mechanism pass. Six of the Mathur types fit none of the four mechanisms: Confirmshaming, Trick Questions, Activity Notification, Testimonials of Uncertain Origin, and — outside Mathur — the three imported Forced Action names. The four Mathur misses share a shape: each falsifies a non-price signal the user reasons with (social evidence, branch labelling, affective framing) without removing a branch, changing the price, compressing time, or raising the exit cost. That is a fourth-category miss: the four-mechanism set covers option set, price, time, and exit, and has no slot for evidence falsification. It is recorded here as a finding, not resolved; the mechanism enum in §2.3 stays at four and those flags carry `"mechanism": null` until a fifth is decided. Two Mathur types (Hidden Subscription, Sneak into Basket) fit two mechanisms and are recorded as such rather than forced into one.

Two properties of this taxonomy matter architecturally. The earlier version said roughly half the pattern types are detectable from the data GlyphAI already ingests; that fraction is UNMEASURED. What is measured, as of this pass, is exactly three keyword-or-ratio rules on listing-shaped fixtures. Whether the rest of the text-side hypotheses hold cannot be stated until the evaluation harness (§6, M3–M4) runs against the Mathur corpus, and the CLI-versus-extension split should be treated as a hypothesis until then. And because Mathur's team verified deceptive instances by re-crawling sites and comparing transient claims (countdowns that reset, stock messages that never change) [VERIFIED 2026-09-09] — the earlier version's specific cadence, "every four hours for five days", is [UNVERIFIED]; the paper was not retrievable and no excerpt confirmed it — the single most powerful detector upgrade is not a smarter model but memory: a price- and claim-history store that lets GlyphAI check whether "only 3 left" was also true last Tuesday (Mathur et al., arXiv).
2.2 What the detection literature says actually works
Automated dark-pattern detection has now been attacked with classical ML, deep learning, computer vision, and large multimodal models, and the results converge on one conclusion: no single technique is good enough alone. AidUI, a computer-vision-plus-NLP system analyzing UI screenshots across ten pattern types, achieved overall precision 0.66, recall 0.67, F1 0.65 [VERIFIED 2026-09-09], with some pattern categories exceeding F1 0.82 [UNVERIFIED] and localization accuracy around IoU 0.84 [VERIFIED 2026-09-09] — strong at finding where manipulation lives in an interface, mediocre at deciding whether it is manipulation (Springer AI & Ethics). Deep-learning pipelines (DBN feature extraction feeding MLP classifiers) and earlier Random-Forest and AdaBoost approaches show the same shape: respectable aggregate numbers driven by high performance on a few easy pattern types and poor performance on the subtle ones (ACM BDMIP).

The LLM generation of detectors improves adaptability and explainability but introduces its own failure mode. DPDGPT runs a multi-stage multimodal pipeline — extraction, initial inference, verification against known pattern features, advanced inference — over a dataset of 1,524 mobile UIs containing 1,871 instances across 13 types [VERIFIED 2026-09-09] plus 85 web UIs [UNVERIFIED], explicitly because monolithic prompting proved unreliable (SSRN). MAS-DPD goes further, splitting detection across specialized Text, Visual, and Interaction agents covering 17 pattern types [VERIFIED 2026-09-09], with a negotiation-based consensus mechanism and targeted false-positive mitigation for notoriously noisy types like Disguised Ad and Limited Time Message (ACM ICAIC). A 2026 head-to-head study [VERIFIED 2026-09-09] found modern LLMs can detect human-created dark patterns, but UX experts still significantly outperform LLMs on novel patterns, and a comparative tool study warns of an "illusion of automated precision" when generative scores are treated as measurements rather than screening signals (Springer AI & Ethics, MDPI Applied Sciences).
The design lesson for GlyphAI is a screening-versus-adjudication split. Cheap, deterministic, auditable rules — keyword families, price-ratio math, DOM structure checks, price-history cross-references — should do the screening and produce evidence; expensive probabilistic methods (an optional local model, or an LLM call if the user opts in) should do second-opinion adjudication on ambiguous cases, and their output should be labeled as probabilistic in the verdict output. This matches both the literature and GlyphAI's existing philosophy: the current codebase never fabricates a number, and a model layer that emits unlabeled confidence would violate that ethic. The consensus-voting trick from MAS-DPD also has a stdlib-compatible analogue: run several independent heuristic detectors per pattern type and require agreement thresholds, which costs nothing but code.
2.3 Proposed architecture: a three-layer detector with a signed pattern database
The proposed Manipulation Detector v2 keeps everything that works in the current module — the simple scan_listing(product_data) -> flags contract, the flag shape {type, severity, evidence} — and restructures the internals into three layers. Layer 1 is a pattern database: a versioned, signed JSON document (stdlib json + hmac/hashlib for integrity) containing per-pattern-type detection assets — phrase families with per-phrase weights, regexes for timer and stock markup, fee-field names for drip-pricing detection, and known third-party widget signatures from the Mathur crawl's vendor list. Moving patterns from code to data is what unlocks the ROADMAP's "community-maintained manipulation patterns" item: contributors edit JSON, not Python, and the project can ship pattern updates without code releases. The Stanford Dark Patterns Tip Line and Brignull's Hall of Shame demonstrate that crowd-sourced pattern collection works as a community practice; GlyphAI's contribution would be making the collection machine-readable and signed (Fairpatterns).
Layer 2 is structural heuristics — deterministic checks that go beyond text: was-price/now-price ratio math (already present), fee-delta detection between advertised price and checkout total where structured offers expose it, subscription-default detection in microdata, and cross-page consistency checks (does the JSON-LD price match the meta-tag price match the visible price). Layer 2 is also where price history becomes a detection input: a TEMPORAL_INCONSISTENCY flag that fires when a countdown resets, a was-price changes between visits, or "low stock" persists for weeks is a strictly stronger signal than any keyword, and it is impossible without the storage subsystem specified in §4.1. Layer 3 is the optional model layer: for users who accept dependencies, a small ONNX classifier or an opt-in LLM adjudication pass on cases where Layers 1–2 disagree or fire weakly; for stdlib purists, Layer 3 is simply absent and the consensus rule among Layer 1/2 detectors tightens. Every flag, regardless of layer, keeps the existing evidence string — because the entire point of GlyphAI is that the user can read why.

Four fields do new work. confidence distinguishes deterministic rules from probabilistic model output, preserving the project's truth-labeling ethic inside the data model itself. mechanism is the detection axis from §2.1 — one of OPTION_SET_ATTACK, MAGNITUDE_ATTACK, TIME_ATTACK, EXIT_ATTACK, or null for the patterns §2.1 records as fitting none; detectors and severity models are keyed on it, so the countdown-timer and low-stock rules share one implementation, while category and pattern_id keep the Mathur vocabulary for reporting and regulatory mapping. pattern_id links each flag to a stable taxonomy node, which is what makes community contributions mergeable and makes severity calibration possible across releases; ids under mathur-2019/ are limited to the 15 types that paper enumerates (§2.1). regulatory connects the flag to the enforcement frameworks detailed in §2.4 — turning a warning into a citation the user could paste into a complaint to the FTC, a state attorney general, or an EU Digital Services Coordinator.
2.4 Regulatory mapping as a first-class feature
The regulatory environment has quietly become GlyphAI's biggest ally. In the United States, the FTC's Rule on Unfair or Deceptive Fees (16 C.F.R. Part 464) took effect on May 12, 2025 [VERIFIED 2026-09-09], prohibiting bait-and-switch pricing and hidden mandatory fees in live-event ticketing and short-term lodging, with civil penalties of up to $53,088 per violation under the 2025 inflation adjustment [VERIFIED 2026-09-09] — and the FTC has warned that Section 5 authority extends to deceptive pricing in other industries (FTC, OnlineAndOnPoint). The Click-to-Cancel rule was vacated by the Eighth Circuit on July 8, 2025 on procedural grounds [VERIFIED 2026-09-09], but the FTC continues enforcement against subscription traps under existing Section 5 authority, and roughly half of US states now have or are advancing their own fee-transparency and dark-pattern statutes [UNVERIFIED] — Texas extracted a $9.5 million settlement from Booking Holdings in August 2025 over undisclosed mandatory fees under its general UDAP statute [VERIFIED 2026-09-09], without any fee-specific law at all (Pandectes, OnlineAndOnPoint).
In the EU, DSA Article 25 prohibits online platforms from designing interfaces that "deceive or manipulate" users or materially distort their ability to make free and informed decisions, with fines up to 6% of global annual turnover [VERIFIED 2026-09-09], and the Commission's 2026 work programme schedules the Digital Fairness Act proposal for Q4 2026 [VERIFIED 2026-09-09] [PROJECTED as an outcome — the proposal has not been presented], targeting dark patterns, personalized pricing, addictive design, and subscription traps across B2C digital services broadly (Cambridge EJRR, European Parliament Legislative Train). A 2025 legal mapping study [VERIFIED 2026-09-09] decomposes Article 25 into three autonomy-violation types — deception, manipulation, and distortion/impairment — which is a ready-made second axis for GlyphAI's flag schema: every pattern type can be tagged with the autonomy violation it commits, aligning the detector's output with the exact language a regulator uses (HAL/Santos et al.).

3. The Jibbelink Protocol
3.1 The 2025–2026 protocol wave changed Jibbelink's job
When jibbelink_format.md was written in mid-2025 [VERIFIED 2026-09-09: repository history dates the file to 2025-07-29], "bot-to-bot negotiation in AI commerce" was a niche idea with no incumbent standards. Fourteen months later the field has consolidated with remarkable speed into a recognizable layered stack, and any Jibbelink redesign must start from an accurate map of it. A2A (Agent2Agent), announced by Google in April 2025 [VERIFIED 2026-09-09] and donated to the Linux Foundation in June 2025 [VERIFIED 2026-09-09], is the communication layer: JSON-RPC messaging between opaque agents, with discovery via signed Agent Cards at /.well-known/agent-card.json (Google Developers Blog, A2A spec). AP2 (Agent Payments Protocol), announced September 16, 2025 with over 60 supporting organizations [VERIFIED 2026-09-09] and donated to the FIDO Alliance on April 28, 2026 [VERIFIED 2026-09-09], is the authorization layer: cryptographically signed Intent, Cart, and Payment Mandates that create non-repudiable proof of what the user authorized, with v0.2 adding "Human Not Present" autonomous transactions [VERIFIED 2026-09-09] (Google Blog, Fintech Magazine).
The commerce layer itself forked into two visions. ACP (OpenAI/Stripe, September 29, 2025) [VERIFIED 2026-09-09] is a checkout-centric spec — product feeds, agentic checkout sessions, delegated payment tokens — live in ChatGPT with Etsy merchants at launch, with Shopify merchants announced as coming [STALE-RISK Sept 2025: whether Shopify checkout went live was not re-checked] (ACP GitHub, Stripe Docs). UCP (Universal Commerce Protocol), launched January 11, 2026 by Google and Shopify with Etsy, Wayfair, Target, and Walmart as co-developers [VERIFIED 2026-09-09] and endorsements from Visa, Mastercard, Stripe and roughly twenty others [VERIFIED 2026-09-09] — the earlier version also named Amazon as an endorser; Amazon appears in none of the endorser lists retrieved this pass, so that name is [UNVERIFIED] — is the broader play: it spans discovery, cart, checkout, fulfillment, and post-purchase, defines a capability-negotiation mechanism where businesses advertise versioned services and extensions at a well-known profile endpoint, and signs everything with RFC 9421 HTTP Message Signatures [STALE-RISK Jan 2026 spec; not re-checked] (Google Developers Blog, UCP spec, Ken Huang analysis). 3.2 The adversarial turn, corrected: honest identity is still load-bearing, for a different reason
The most-cited external event for GlyphAI's architecture is Amazon v. Perplexity, and the earlier version of this section was built on a theory that has since been vacated. The record as retrieved this pass: Amazon sued in November 2025 over Perplexity's Comet browser agent shopping inside customers' logged-in Amazon accounts while sending Chrome's user-agent string rather than one identifying the agent [VERIFIED 2026-09-09]. On March 9, 2026 (reported March 10), Judge Maxine Chesney granted a preliminary injunction, finding Amazon likely to succeed on CFAA and California CDAFA claims because Comet accessed accounts "with the Amazon user's permission, but without authorization by Amazon" [VERIFIED 2026-09-09]. The Ninth Circuit stayed the injunction on March 16, 2026 [VERIFIED 2026-09-09], heard argument on June 11, 2026 in Seattle [VERIFIED 2026-09-09], and on August 4, 2026, in Amazon.com Services LLC v. Perplexity AI, Inc., No. 26-1444, vacated the injunction and remanded [VERIFIED 2026-09-09 — the holding is taken from independent law-firm and press summaries (Cooley, Wilson Sonsini, Ropes & Gray, Ballard Spahr, Troutman, Eric Goldman, PYMNTS); the opinion PDF at cdn.ca9.uscourts.gov was not retrievable, so the quoted phrases below are as those summaries quote them]. The holding, on that preliminary record: when a user directs the agent to act on Amazon.com, it is the user who "accessed" Amazon's computers; the Assistant is "a tool, not a person" for the statute's purposes; Amazon was therefore unlikely to succeed on its CFAA and CDAFA claims, and its irreparable-harm showing was weak. Two limits matter. It is a preliminary-injunction ruling, not a merits judgment, and the pleaded CFAA and CDAFA claims continue in the district court on remand [VERIFIED 2026-09-09]. And the panel confined itself to CFAA and CDAFA; the summaries report it did not foreclose breach-of-contract, unfair-competition, tortious-interference, or state consumer-protection theories [VERIFIED 2026-09-09, from secondary summaries only]. Amazon separately updated its Business Solutions Agreement effective March 4, 2026 to require agents acting on seller accounts to identify themselves as automated and to stop on request [VERIFIED 2026-09-09], and its commercial motive is plain: agents that skip search pages skip the sponsored listings that generated $68.6 billion in 2025 ad revenue [VERIFIED 2026-09-09] (Decrypt).
What this does to the earlier argument. The premise that "a user's permission does not authorize their agent on a platform" is the district court's theory — the vacated theory — and cannot stand as written. As of this pass the controlling appellate statement in the Ninth Circuit is the opposite, subject to the merits. Three consequences follow for GlyphAI.
First, the Web Bot Auth recommendation stands, but on different grounds. The commercial grounds are untouched: Shopify has, since May 7, 2026, put unsigned bots and agents on its strictest Storefront-API and hosted-page rate tier while Web Bot Auth-signed agents pass [VERIFIED 2026-09-09]; Cloudflare's defaults taking effect September 15, 2026 block the "Agent" category on ad-carrying pages for new domains, new customers, and Free-tier zones, with an opt-out window [VERIFIED 2026-09-09] (the earlier version omitted that scope qualifier). Web Bot Auth itself — RFC 9421 signatures plus a key directory at a well-known URI, verifiable at the CDN edge by Akamai and Cloudflare — is deployed ahead of standardisation; it remains an individual IETF draft as of this pass [VERIFIED 2026-09-09] (Akamai, Zuplo). A GlyphAI fetcher that can prove its identity works where an unsigned one degrades. The legal-exposure ground — that signing keeps GlyphAI on the right side of a CFAA line the courts were about to draw — is gone; the Ninth Circuit drew the line on the other side. Signing is now justified as rate-tier access and protocol hygiene, not as a legal shield.
Second, honest identification is still load-bearing, for a reason the case record makes concrete. Comet's non-use of a distinct user-agent string appears in the record as what prevented Amazon from identifying the agent [VERIFIED 2026-09-09] (secondary summaries). Under the Ninth Circuit's reading that fact did not create CFAA liability — but it is exactly the fact that turned a policy disagreement into a lawsuit, an injunction, and a platform rule change. Identification is what lets a platform apply its own rules to agent traffic instead of litigating: robots.txt, terms of service, rate tiers, and Amazon's new agent policy are all mechanisms that only work on traffic that can be recognised. GlyphAI identifies itself because the platform's right to say no is real even where the CFAA does not enforce it, and a fetcher that can be recognised can be told. The project's stance was never that identification was legally required; it is that a tool built to resist manipulation does not get to disguise itself, and that stance is unaffected by the vacatur.
Third, the ROADMAP's "legal defense fund for scraping challenges" is re-graded, not deleted. It is no longer hedging against a CFAA theory under which any platform-unauthorised agent access is a federal violation; that theory is vacated. It now hedges against the non-CFAA theories the panel left open (breach of terms of service, trespass to chattels, unfair competition), against the merits phase in the district court reaching a different answer on a fuller record, and against a circuit split or Supreme Court review [PROJECTED]. hiQ v. LinkedIn is the template for that residual exposure: the Ninth Circuit's CFAA holding favoured the scraper, and the case still ended in December 2022 with a $500,000 judgment against hiQ, a permanent injunction, and destruction of the scraped data, on contract and trespass theories [VERIFIED 2026-09-09] (Lection case analysis). Public, unauthenticated, robots-respecting, honestly-identified fetching remains the zone of minimum exposure under those theories, and it is where GlyphAI already lives. The residual risk is contract and tort, not computer fraud.
3.3 Repositioning: Jibbelink is the negotiation and values layer, not a commerce protocol
The original Jibbelink spec describes "a transparent negotiation protocol for AI-to-AI economic interaction based on user glyph profiles." Read against the 2026 landscape, every part of that sentence except "negotiation" and "glyph profiles" is now covered by funded, governed, industry-backed standards — messaging (A2A), checkout (ACP/UCP), payment authorization (AP2), settlement (x402), bot identity (Web Bot Auth). Competing with any of them would be a category error for an MIT-licensed project with a volunteer community. But no incumbent protocol carries the user's values into the transaction: UCP negotiates capabilities (which checkout extensions both sides support), AP2 proves authorization (did the user approve this cart), and neither expresses preference (is this vendor's behavior acceptable to this buyer, and at what price does the deal stop being worth it). That is the open niche, and it is exactly Jibbelink's original niche.
The repositioned Jibbelink v0.2 therefore has three jobs and only three jobs. First, values exchange: conveying a privacy-preserving summary of the buyer's glyph constraints (budget ceiling, ethical floor, DIY fallback threshold) — with Selective Disclosure in the Verifiable Intent sense, so the counterparty learns the minimum necessary (Mastercard). Second, offer negotiation: a structured alternating-offers dialogue over price, bundle, delivery, and terms, governed by the strategy machinery in §3.5. Third, audit: producing a signed, hash-chained transcript the user can inspect — the "real-time negotiation transcript viewer" on the existing roadmap, but tamper-evident. Where a merchant speaks UCP or ACP, Jibbelink rides as an extension or a pre-negotiation layer and hands off to the incumbent protocol for checkout; where a merchant speaks nothing, Jibbelink falls back to what GlyphAI does today — analysis, verdicts, and alternatives. This "bridge, don't replace" stance also de-risks adoption: GlyphAI never needs merchant cooperation to be useful, and every merchant that adopts UCP makes Jibbelink more useful, not less.
The legal framing supports this positioning. Consumer Reports' innovation lab published a design study of personal AI agents distinguishing an Intermediary path — the agent acts under its own identity with explicitly delegated, granular permissions, making the user the legal principal and the agent's provider the legal agent — from a credential-reuse path where the agent impersonates the user's session (Consumer Reports). Amazon v. Perplexity no longer supports the reading that the credential-reuse path is unlawful: the Ninth Circuit held on the preliminary record that the customer, not the agent's developer, is the one accessing [VERIFIED 2026-09-09], which — if it holds on the merits — makes that path lawful under the CFAA. What the case did demonstrate is the cost of the credential-reuse path in every other dimension: a year of litigation, a district-court injunction, and a platform rule change (§3.2) that the intermediary path — explicit identity, explicit delegation, explicit scope — avoids by design. The intermediary path is preferred here on those grounds and on the project's own values, not on a legal necessity the courts have not established. Jibbelink v0.2's identity and mandate machinery (§3.4) is precisely the intermediary path implemented in protocol form.
3.4 Jibbelink v0.2: envelope, signing, identity, and mandates
The v0.1 message format mixes transport, content, and context in one flat object and ships unsigned. The v0.2 redesign separates four concerns. Envelope: protocol_version, message_id, in_reply_to, timestamp, sender/recipient (now DID strings, not free text), and message_type from an expanded set — OFFER, COUNTER, ACCEPT, REJECT, WALK, QUERY, DISCLOSE, AUDIT — where WALK (walk away) is a first-class citizen because a loyalty-bound agent's strongest move is refusing, and AUDIT requests the counterparty's signed view of the transcript. Payload: type-specific content; an OFFER payload keeps v0.1's proposed_price, currency, negotiation_context, and human-readable rationale (rationale is a genuinely good idea — it makes bot behavior inspectable — and predates the industry's discovery of the same need). Proof: an Ed25519 signature over a canonical serialization of envelope+payload, plus created/expires for replay protection, following the parameter discipline of RFC 9421 [STALE-RISK RFC 9421, 2024; not re-checked] (UCP signatures spec). Transcript chain: each message carries prev_hash, the SHA-256 of the prior message's canonical form, so the whole negotiation is a hash chain either party can prove was not edited.
The signing design is where the two-track dependency decision gets concrete, and the news is good for the stdlib track. Track A (stdlib-only): Ed25519 can be implemented in pure Python using only hashlib — the IETF itself ships a complete reference implementation as Appendix A of RFC 8032 [STALE-RISK RFC 8032, 2017; not re-checked], with the explicit caveats that it is slow and makes no attempt at side-channel resistance (RFC 8032). For a negotiation protocol where an agent signs a handful of messages per session on a personal machine, "slow" (tens of milliseconds per signature) is irrelevant and side-channel exposure is minimal; a hardened pure-Python Ed25519 of a few hundred lines is a legitimate stdlib-only answer. Track B (dependency): PyNaCl or cryptography gives constant-time, audited Ed25519 — the right choice the moment GlyphAI signs at volume (the mesh scenario) or runs on shared machines. The correct architecture is a signing.py module with a backend protocol: pure-Python fallback always present, fast backend auto-detected, identical interface. JSON canonicalization must be pinned (sorted keys, no whitespace, UTF-8, explicit float formatting) because a signature over ambiguous serialization is worthless; UCP dodges this by hashing raw body bytes via Content-Digest, which Jibbelink should adopt for its HTTP transport (UCP signatures spec).

Identity should be W3C Decentralized Identifiers, not a registry GlyphAI would have to run. A did:key identifier is self-minted from the agent's Ed25519 public key — zero infrastructure, perfect for the single-user CLI — while did:web anchors an identity to a domain's .well-known directory for bots that want a stable, discoverable presence; DID documents carry public keys and service endpoints, support key rotation without changing the identifier, and contain no personal data (DID/VC agent framework, arXiv, NeuralTrust). This directly implements the ROADMAP's "federated glyph verification" without a centralized "glyph-verify.org" (which the v0.1 security sketch assumed someone would have to build and trust). Finally, the glyph intent mandate: before any negotiation, the user (or the local GlyphAI instance on the user's behalf) signs a mandate — glyph hash, scope (product class, budget ceiling, expiry), and constraints — modeled on AP2's Intent Mandate and Verifiable Intent's identity-plus-instructions-plus-outcome record (Google Blog, IDTechWire). The loyalty oath stops being a string in a JSON file and becomes a cryptographic statement of delegation: the agent carries proof of whose values it serves and what it may not accept. That is the oath, enforced.
3.5 Negotiation mechanics: fifteen years of ANAC research is free for the taking
Jibbelink v0.1's negotiation_context (urgency, budget_flex, ethical_threshold, DIY_viability) is a gesture toward strategy with no machinery behind it. The automated-negotiation research community has spent fifteen years building exactly that machinery in the Automated Negotiating Agents Competition (ANAC), run annually since 2010 — first at AAMAS 2010, in later years alongside AAMAS or IJCAI [VERIFIED 2026-09-09; the earlier version's "at IJCAI since 2010" was wrong] — and its canonical protocol — the Stacked Alternating Offers Protocol (SAOP) — is a natural fit: two parties alternate offers over a multi-issue outcome space with a hard deadline, and failure to agree by the deadline yields the disagreement outcome (ANAC 2025, arXiv, EmergentMind ANAC overview). ANAC's core concepts translate one-to-one into Jibbelink terms: the utility function is computed from the glyph (a linear additive function over issues — price, delivery time, warranty, vendor-ethics score — weighted by glyph values is the standard ANAC form); the reservation value is the walk-away point, which in GlyphAI's case has a uniquely honest definition — the price at which the DIY alternative or the geographic alternative wins; and the deadline/discount factor maps to the glyph's urgency value.
Strategy-wise, ANAC winners decompose into bidding, acceptance, and opponent-modeling components (the BOA framework), and the well-known concession curves — Boulware (concede little until the deadline looms) versus time-based conceders — are a few lines of Python each (TU Delft ANAC). GlyphAI's negotiation personality should derive from the glyph: high DIY_viability and low urgency yield a hard Boulware agent with a low reservation value, because the user's outside option (make it, fix it, buy it in town) is strong; high urgency and high budget_flex yield a faster-conceding agent. For the dependency track, NegMAS — a mature, pure-Python negotiation library behind recent ANAC leagues — offers SAOP mechanisms, utility-function classes, concession strategies, opponent models, and even a negotiate CLI, meaning the entire negotiation core could be prototyped against ANAC-hardened opponent agents before Jibbelink ever talks to a real vendor bot (NegMAS GitHub, NegMAS docs).
Two design cautions come from the research rather than the engineering. First, ANAC agents negotiate over utility, and a glyph-derived utility function must never leak the user's full value profile: revealing your reservation value or your ethical floor to a counterparty is an invitation to be gamed, so the DISCLOSE message type should follow Selective Disclosure — the counterparty sees offer-relevant constraints ("max budget for this session"), never the glyph itself (Mastercard). Second, negotiation with a manipulative counterparty is itself an attack surface: a vendor bot that detects a GlyphAI agent could present fake "negotiated discounts" anchored to inflated prices — which loops back to §2.3, because the detector's price-history layer is precisely what immunizes the negotiator against negotiated-price anchoring. The detector and the negotiator are not two features; they are one immune system.
3.6 The glyph bot mesh: discovery, trust, and federated verification
The ROADMAP's Phase 3 dreams of an "optional mesh network of glyph-aligned bots" and "federated glyph verification." The 2026 protocol stack supplies the parts. Discovery copies the A2A Agent Card pattern: each mesh participant publishes a signed Glyph Card at a well-known URI (/.well-known/glyph-agent.json) declaring its DID, its public key, the Jibbelink versions it speaks, and its capabilities (price-watching, pattern-sighting reports, DIY knowledge packs) — A2A registers exactly this well-known pattern with IANA [UNVERIFIED] and supports JWS-signed cards [STALE-RISK; A2A spec not re-checked], so the precedent is production-grade (A2A spec). Trust starts as a personal web of trust — the user pins the DIDs of bots they trust (friends, family, a local co-op) — which fits GlyphAI's sovereignty ethic far better than any global reputation database, and requires nothing beyond sqlite3 and Ed25519 verification.
The genuinely novel mesh service is shared manipulation intelligence: signed pattern-sighting reports (site X served countdown timer that resets; evidence hash; timestamp; reporter DID) that aggregate into the community pattern database from §2.3. This is the Stanford Tip Line made cryptographic — reports are attributable (signed), privacy-preserving (the reporter's glyph is never exposed), and spam-resistant (trust-weighted by the web of trust) (Fairpatterns). A mesh of a few dozen bots watching disjoint slices of the retail web would generate a manipulation telemetry stream that no single consumer tool currently produces, and because every report is signed and hash-chained, the dataset itself becomes credible evidence — the kind regulators, journalists, and researchers (who currently have only the 2019 Mathur snapshot) actively lack.
A pragmatic note closes the section: the mesh is Phase 3 for a reason. Every component above is independently useful — signed fetch requests help even a solo user under Shopify's WBA rate limits, the pattern DB helps offline, the DID identity is minted locally — so the mesh can grow organically from a single reference implementation without a cold-start problem. This is the same adoption logic the UCP designers used with capability profiles: publish a manifest, let counterparties discover you when they care to (UCP spec).

4. Supporting Subsystems
4.1 Price history: the truth anchor the detector is missing
The ROADMAP lists "price history tracking" as an unchecked Phase-1 item, and §2.3 showed it is load-bearing for the detector's strongest future flags. The stdlib-only implementation is genuinely trivial: Python ships sqlite3 in the standard library, so a price_history.db with three tables — products(url, product_id, name, first_seen), observations(product_id, ts, price, was_price, availability, source_hash), and claims(product_id, ts, claim_type, claim_text) — covers the design space. The third table is the subtle one: recording claims ("only 3 left", "ends tonight") with timestamps is what powers COUNTDOWN_RESET and STALE_SCARCITY flags, replicating in miniature the re-crawl methodology Mathur's team used to prove deception empirically (Mathur et al., arXiv).
The ecosystem validates the design while clarifying GlyphAI's lane. Self-hosted trackers like PriceGhost and the SQLite-backed price-tracker both demonstrate the cascading-extraction pattern (JSON-LD → microdata → OpenGraph → CSS/regex fallbacks) that GlyphAI's price_extractor.py already implements in stdlib form, and both add notification plumbing and per-seller history that GlyphAI can borrow architecturally (PriceGhost, price-tracker). Commercial price-history data (Keepa's token-metered API: €49/month entry tier [VERIFIED 2026-09-09]; the ceiling is reported at €4,499/month by the source the earlier version used and at €11,099/month by a 2026 pricing review — [STALE-RISK] on the upper figure) is priced for resellers, not consumers, and importing it would sit awkwardly with the loyalty oath's data-sovereignty logic anyway (FBAMultiTool). The honest conclusion: GlyphAI should build personal price history (everything you have looked at, remembered forever — which no commercial tracker sells) and let the mesh (§3.6) eventually pool observations across trusted peers.
4.2 The DIY fallback engine: from thin JSON to federated repair knowledge
The DIY engine is GlyphAI's most differentiated feature — no other consumer agent says "don't buy it, fix the one you have" — and its current knowledge base is ten lines of JSON. The highest-leverage upgrade is federation with the iFixit API, the open, JSON-by-default interface to the world's largest free repair-manual library, which exposes step-by-step guides, tools, parts, difficulty ratings, and device hierarchies and was explicitly built to support bandwidth-limited technicians and third-party repair apps (iFixit). Architecturally, diy_knowledge.py should gain a source-priority chain: local knowledge first — entries in the local knowledge base take source priority over any fetched result, as a design requirement — then cached iFixit data, then a live iFixit query when online, with aggressive on-disk caching so the engine degrades gracefully when connectivity is intermittent or absent. Offline operation of the core is a design requirement, not a fallback.
The second upgrade is economic: connect DIY suggestions to the price-history and negotiation subsystems. A DIY alternative is the reservation value in every negotiation (§3.5) and the floor in every verdict — "this item costs $24.99, the driver-board repair is $4 in parts and twenty minutes, here is the guide" is simultaneously a recommendation, a negotiation anchor, and a manipulation antidote. Structuring diy_knowledge.json entries with cost estimates, time estimates, skill requirements, and parts lists turns the DIY engine from a suggestion box into the quantitative backbone of the whole value system — and it is the subsystem where the project's community (people who "fix anything that needs to run") has the most irreplaceable knowledge to contribute.
4.3 Delivery surfaces: browser extension, MCP server, and the watchlist loop
The CLI-plus-scheduler surface set is right for Phase 1, but three additions matter, in priority order. The watchlist loop is cheapest: extend scheduler.py from re-analysis-on-a-timer to a price-and-claim watch that writes to the history store (§4.1) and alerts on threshold crossings — this is what converts one-shot analysis into the temporal detection that catches countdown resets. The MCP server is strategically important: exposing analyze, diy, and profile as Model Context Protocol tools lets any LLM agent the user already runs consult GlyphAI as its value-conscience, which positions GlyphAI as the conscience inside the agentic-commerce wave rather than a bystander to it — and MCP is the same substrate ACP and AP2 build on (Google Dev Forum).
The browser extension (already on the Phase-2 roadmap) is where the DOM-only half of the taxonomy (§2.1) becomes detectable — visual interference, confirmshaming, pre-checked sneaking — and existing open-source extensions prove the pattern works locally and privately: Dark Radar scans pages entirely in-browser with no external calls, and academic extensions demonstrate bait-and-switch and hidden-information detection from DOM analysis (Dark Radar, Dark-Pattern-Identifier). GlyphAI's extension should differ from all of them in one way that matters: it reports through your glyph and attaches your price history, so the warning is not "this page uses a countdown timer" but "this countdown has reset three times since you first looked, and the in-store price 40 miles away is 30% lower." The extension is also the only surface where GlyphAI sees checkout-flow patterns (drip pricing, roach-motel cancellation), which are the patterns regulators care most about (§2.4).

5. The Two-Track Dependency Decision
The stdlib-only constraint is not a limitation to apologize for; it is a trust feature — an auditable, install-anywhere, works-offline core is precisely what a loyalty-bound agent should be, and it is what lets GlyphAI run on low-power hardware over an intermittent link, or with no link at all. Offline operation of the core is a design requirement. The research nonetheless surfaced four places where a dependency buys a capability that cannot be honestly replicated in stdlib Python. The recommended architecture is a hard core / soft extras split: the core never imports anything outside the standard library, and extras are optional packages that register themselves when present (the signing.py backend pattern from §3.4 applied project-wide).

| Capability | Stdlib track (always works) | Dependency track (optional extra) | Verdict |
|---|---|---|---|
| Message signing | Pure-Python Ed25519 per RFC 8032 Appendix A — correct, slow, no side-channel hardening ([RFC 8032](https://tools.ietf.org/html/rfc8032)) | PyNaCl / `cryptography`: constant-time, audited, ~1000× faster | Core ships pure-Python; extra auto-detected |
| Price history | `sqlite3` (stdlib) — fully sufficient | None needed | Stdlib, period |
| Pattern detection L1/L2 | JSON + `re` + `html.parser` — fully sufficient | None needed | Stdlib, period |
| Model-layer adjudication (L3) | Consensus voting among heuristic detectors | ONNX Runtime + small distilled classifier; or opt-in LLM API call | Extra only; never in core |
| Negotiation prototyping | Hand-rolled SAOP loop (~200 lines: offer/counter/deadline/utility) | NegMAS for strategy research and ANAC-opponent testing ([NegMAS](https://github.com/yasserfarouk/negmas)) | Core hand-rolled; NegMAS as dev/research tool |
| DOM-level detection | Not possible headlessly in stdlib | Browser extension (JavaScript, no Python dependency) | Different surface, not a dependency |
| Key storage | File with `os.chmod` 0600 | OS keyring via `keyring` package | Core file-based; extra for desktop users |

The one temptation to resist is embedding an LLM in the core decision path. Beyond the dependency weight, the detection literature's warning about the "illusion of automated precision" applies with double force to a loyalty-bound agent: a verdict the user cannot trace to an evidence string is a verdict GlyphAI's own philosophy forbids (MDPI Applied Sciences). If an LLM is ever consulted, it belongs at the edges — summarizing a negotiation transcript, drafting a complaint letter from a flag's regulatory mapping — never between the evidence and the verdict.

7. Risks, Open Questions, and Honest Uncertainties
The legal ground moved, and it moved against the earlier version of this document. Amazon v. Perplexity was decided at the preliminary-injunction stage on August 4, 2026: the Ninth Circuit vacated the injunction and held, on that record, that the user, not the agent's developer, accesses the platform [VERIFIED 2026-09-09]. The district court's theory — that a user's instruction does not authorize their agent — did not survive that stage. The pleaded CFAA and CDAFA claims continue in the district court [VERIFIED 2026-09-09], so the open questions are whether a fuller merits record changes the answer, and whether Amazon's non-CFAA theories (terms of service, trespass, unfair competition) do the work the CFAA no longer does [PROJECTED]. GlyphAI's position in either outcome is the same as before, for a different reason: its smallness (personal, non-commercial, robots-respecting use looks nothing like Comet's scaled operation inside logged-in accounts) and its refusal to touch authenticated areas leave even the theories the panel left open little to attach to. The ROADMAP's legal-defense line item stays, re-graded per §3.2: it hedges contract and tort exposure and a possible reversal on the merits, not a federal computer-fraud theory. The behavioral asset is unchanged — GlyphAI has never disguised itself — but its value is now that platforms can recognise and rule on its traffic, not that a court requires it.
Protocol betting risk is real but bounded. UCP, ACP, and AP2 are backed by competing coalitions, and while UCP currently has the broadest endorsement list [VERIFIED 2026-09-09], ACP has the largest live deployment (ChatGPT checkout) [STALE-RISK Sept 2025; deployment sizes not re-checked], and the FIDO Alliance's stewardship of AP2 and Verifiable Intent [VERIFIED 2026-09-09] could rearrange the board again (Shopify Spring '26, PYMNTS). GlyphAI's hedge is architectural: by building signing, identity, and negotiation as its own layer and treating UCP/ACP as interchangeable handoff targets, the project is not betting on any winner — it is betting on the gap (values and negotiation) that all winners currently share. If the gap closes — say, UCP adds a preference-negotiation extension — GlyphAI's best move is to become its reference consumer-side implementation, which would be a victory, not a defeat.
Calibration is the quiet hard problem. The detector v2 design is straightforward; deciding severities is not. The literature offers per-type performance benchmarks but no ground-truth severity scale, and GlyphAI's verdicts are only as honest as the numbers behind them. The evaluation harness (M3–M4) therefore matters more than any detector feature: it should report per-pattern-type precision and recall against the Mathur corpus and a hand-labeled local set, publish the numbers, and let severity emerge from measured false-positive costs rather than intuition. A loyalty-bound agent that cannot show its user an accuracy number for each flag type is asking for faith; the whole point of the project is to replace faith with evidence — starting with its own.
